# OracleX Milestone 07 · professional UI progress

Updated 10 November 2026  
Status: **in progress** · Source version remains **1.5.0** until the milestone exit gate is met.

## Implemented source work

- Added canonical routes for Overview, Documents and version detail, Ask and saved conversations, Requests and record detail, My work, People, Teams, Roles, Audit and System status. Existing request query links still resolve. Sign-in returns to an authorized route; browser back/forward retains route state.
- Rebuilt Overview, My work, People, Teams, Roles and Audit with opaque, restrained business UI. System status distinguishes a missing configured model from an unavailable runtime and reports only measured health.
- Added shared page headings, notices, status labels, empty/error states and a common modal focus boundary. Request creation, upload, document details and administrator dialogs contain keyboard focus, make the background inert, close with Escape and restore focus. Closed mobile navigation is inert; its open drawer uses the same boundary. A skip link and menu expanded-state announcement are included.
- Added mobile record layouts for My work, People, Teams and Audit. The previously checked views had no page-width overflow at 390 CSS pixels.
- Rebuilt the first-company setup form with explicit field labels, responsive columns and no invented company domain. Removed unused prototype pages and remaining page/component inline styles.
- Added a short-lived, in-memory server-state cache keyed by company and user for profile, teams, roles, people and tasks. Page unmount and logout cancel outstanding reads; successful writes invalidate cached entries and cause in-flight GETs to restart before their result reaches the page. Other sensitive reads fetch fresh.
- Generated frontend schema types from live FastAPI OpenAPI and added a drift check. Every named response type in the shared frontend type module now aliases a generated schema. Optional permissions and flags are handled explicitly; task writes use generated input schemas. Company setup now correctly expects a token/user response, and bootstrap status has a typed backend response.
- Request payloads use `unknown` with guarded text/number readers; editing preserves other fields, zero cost is retained, and cleared numeric/date/select fields send null rather than invalid empty strings.
- Added authenticated, typed model-health and audit-integrity responses. Audit now loads 25 records at a time with a stable timestamp/ID cursor. Filter and pagination requests cancel when replaced, preventing older pages from being appended to a newer filter.
- Added typed backend responses for team deletion and assistant feedback, with focused checks of the response and persisted feedback record.
- Prevented deletion of a team while people, documents, tasks or workflows still reference it. Added a conditional Alembic repair migration for an older Milestone 06-stamped database missing two conversation columns.
- Kept Documents and Requests mounted across record URL changes. This restores opener focus and avoids cancelling the document preview during its own state update. Replaced document-opening reads are cancelled. Selecting an already-active request view no longer leaves the register stuck loading.
- Removed conflicting form autofocus and the preselected administrator-role default in Add person. New accounts start with role and team unassigned.
- Darkened muted text and focus outlines, connected shared field hints to their controls, labeled document search/replacement and the assistant composer, and made assistant scrolling honor the reduced-motion preference.
- Added field-specific validation error messages that retain HTTP status and omit echoed input. History, archive and copy failures are handled; a history failure has a retry control and does not claim there are no saved conversations. Failed task-assignee lookup is explicit and disables assignment until recovery. Documents show unavailable counts during a failed initial read.
- Added mobile saved-conversation selection and history retry below 720 CSS pixels. Long conversation titles wrap and the Archive action stays in view.

## Sixth batch: live ingestion and shared search service, 20 October

- Confirmed and fixed a stale detail panel: queued uploads and replacement jobs now refresh their status, immutable version history and current extracted preview without reopening. Replacement jobs continue polling even while the previous document is Ready. Reads cancel when the record changes/closes; update failures have an explicit retry.
- Current version reflects the active version ID; the register labels its separate version count as a total. Upload/replacement/retry feedback stays inside the active dialog. Busy actions cannot be repeated or dismissed mid-request. The shared modal boundary restores focus when submission disables or removes its focused action.
- Found a cross-process embedded-index failure: after a separate worker replaced a version, the running API returned no search results while a fresh process found the new vectors. API and worker now use one local Chroma HTTP server. Production requires its host, and the non-test worker refuses embedded storage. Compose gives only that server ownership of the existing index volume, without publishing its port or adding a new image dependency.
- Search backend failures now return a safe 503 instead of an empty result. Old search results clear when a new search starts. Native startup checks the configured index server and starts the ingestion worker; setup/deployment instructions describe the required server and migration path.
- The live fixture retained version 1 during an intentionally missing version-2 source. Restoring that exact synthetic file and selecting Retry recovered version 2. A further version-3 replacement completed through the separate worker while API and Chroma stayed running; UI preview and search both showed ELM-115. Stopping/restarting Chroma produced a visible search error and successful retry without restarting the API.
- Local processing used the existing deterministic embedding, not an approved semantic model. The document search still exposes nearest-neighbor similarities, including weak/unrelated candidates; company relevance acceptance remains open. Native service checks do not prove container behavior or air-gap isolation.

Local record/view/reload controls ask before discarding dirty fields; at the end of that batch, protection across sidebar navigation, browser history and page unload was still unfinished. The eighth batch below extends it.
- Added owner cancellation with a required reason and retained timeline event. Review controls match backend ownership/assignment rules; non-assigned reviewers do not receive decision controls. Approved records explicitly say completion has not been recorded, and completion uses its own note/action.
- Replaced competing record/list reads with cancellable effects, added loading/unavailable/retry states and explicit record/register reload controls. A 409 conflict retains the current fields and blocks further actions pending reload. Refreshing a list that reveals a newer lock version also requires review before another action. History visits fetch fresh records, and fresh details update matching register rows.
- New request and document upload controls now use actual capabilities. Employees without `doc:upload` do not see upload; non-administrators cannot select classifications above their clearance. Shared notices place draft-validation feedback inside its dialog. New/reloaded records and unavailable states receive focus; register refresh remains focusable while loading.
- The live browser exposed an unhandled nested-payload validation error: currency `ZZ` returned 500. Invalid typed fields now return a safe field-specific 422, with a plain-language currency message and no echoed input. Required request text and decision/completion/cancellation notes reject whitespace-only values. A rejected update leaves the saved version, lock and payload intact.

## Eighth batch: notification inbox and pending request text, 20 October

- Added a recipient inbox at `/notifications`, available from workspace navigation. It provides All/Unread filters, read status, explicit mark-as-read, request opening, refresh/retry, empty/error states and 25-record cursor pagination. The loaded count is not presented as a global unread total. Opening a record does not silently mark its notification read.
- The API preserves its list response and default limit, adding paired timestamp/ID cursor parameters with a bounded page size. Recipient and company filters apply to both listing and marking read. A fixed cursor survives removal of a page-tail unread item; replaced reads cancel and pagination deduplicates IDs.
- Notification buttons derive local request URLs from validated request IDs. A supplied external `deep_link` is ignored. Notification dates interpret legacy suffix-free API timestamps as UTC and preserve explicit offsets.
- Pending new request text, existing draft edits, reviewer notes and cancellation notes use a company/user-scoped memory buffer. Sidebar navigation and browser history can leave a record and restore its text later. A header indicator opens a resume/discard list; saving a draft persists its fields to the backend. Saving fields retains an unsent cancellation note.
- Successful writes cannot erase newer pending text from another page lifetime. Restoring text based on a stale saved version shows the existing reload-required state and blocks writes while preserving the old fields for inspection.
- Sign-out uses the shared focus-managed confirmation dialog. Keep working and Escape retain pending text; confirmed sign-out discards that account's buffer. A native `beforeunload` handler requests a reload/close warning when text remains. **The automated browser reloaded without exposing this warning, so its real-browser behavior remains unverified.** Memory-only text does not survive an accepted reload, crash or process loss. No request text is written to localStorage/sessionStorage.
- Browser evidence: Arya saw 25 then all 30 own notifications (27 labeled QA plus three earlier records), without Krish's QA 27. Marking the page-tail QA 02 read in Unread removed it, focused feedback and still allowed older records to load; refresh retained the read state. An unsafe-link fixture opened only its local request. Krish saw only his QA notification; an API outage kept the failed mark unread, displayed a load error and recovered after restart. Marking his notification read then selecting Unread showed the empty state.
- A synthetic purchase draft resumed after closing its dialog, navigating to Notifications and browser Back; title, description and zero cost survived. It saved as record `b9d8a53f-0c06-40ac-a94b-b7aeb9f4c607`. Existing-record title/cancellation text survived workspace navigation. A second view saved version 3; the first view restored its pending version-2 fields with writes blocked. Sign-out cancellation, explicit discard, Escape/focus return and sequential account cleanup were observed.
- Inbox and the pending-text header fit selected 390/768/1440 CSS-pixel viewports. Screenshot: `OracleX-M07-Notifications-20261020.jpg`. Long-content, all-page accessibility and target-host/session matrices remain open.

## Ninth batch: reviewer selection and request journeys

Source and selected live browser checks completed on 20 October 2026; publication verification refreshed on 10 November 2026.

- New-request and draft-edit forms offer an active company reviewer or the unassigned review queue. A minimal endpoint exposes only reviewer ID, name and job title, excludes the requester, and checks company, capability and record access.
- Reviewer changes count as unsaved draft changes, block submission until saved, survive the pending-text buffer and become part of immutable versions. Submission revalidates eligibility; inactive or permission-revoked reviewers leave the draft unchanged with a safe 422.
- Submitted review can be assigned; reassignment is limited to the assigned reviewer or an authorized administrator. Version conflicts and duplicate assignment are rejected. Assignment preserves the exact submitted version, records its new reviewer in the timeline, and notifies the new reviewer, previous reviewer and requester.
- Synthetic browser access journey: Arya selected Ashutosh, submitted version 1, Ashutosh reassigned to Hetvi, and Hetvi rejected with a reason. Arya read the rejection and had no decision or completion controls. No access was granted.
- Synthetic browser controlled-change journey: a draft reviewer change required saved version 2 before submission; Hetvi approved that version and separately recorded QA completion. No production process or external system was changed.
- Requester cancellation while Submitted and Assigned retained reasons. Reviewer lookup failed visibly during an API outage, then retried without losing entered text. Selecting a reviewer survived closing/reopening the new-draft dialog. Selected form/page widths fit 390/768/1440 CSS pixels.
- Eight new backend cases cover minimal/scoped reviewer choices, assignment authority, stable submitted versions, recipient notifications, access/change terminal journeys, cancellation and reviewer revocation. Existing frontend tests gained reviewer dirty-state, scope and assignment assertions.
- Browser evidence uses disposable SQLite and sequential role sign-ins from 20 October. It does not establish independent PostgreSQL sessions, a full browser race matrix or company acceptance. Native unload prompts, durable draft recovery, all-page accessibility and target-host gates remain open.
